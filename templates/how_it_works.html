NEXARION ARCHITECTURE

HOW NEX WORKS

What each part does, why it exists, and where it's headed

NEX is built from a handful of systems that run underneath the dashboards you see on the other pages. This page explains each one in plain language: what it actually does today, why it was built that way, and how it fits the long-term idea of NEX becoming steadily more capable and more autonomous — in deliberate, human-supervised steps rather than all at once.

STATUS KEY Live running automatically, all the time Manual built and working, but only runs when you trigger it Dormant built, but not currently wired in or running
THE THINKING LOOP

The Two-Brain Loop

Live

NEX is always thinking, not just while you're chatting. A background loop runs every ~30 seconds around the clock, independent of this window — deciding what to research, arguing a position internally, updating memory. Talking to NEX in chat is a second, faster path into the same mind.

Why two models? A fast model handles anything you're waiting on — your chat replies, and the quick decisions inside each background cycle. A slower, more capable model is reserved for expensive background work — deep research, resolving contradictions, extracting relationships between ideas — nobody's watching a spinner for that, so it can afford to take its time.

Chat model: fast, fits fully on the GPU Deep model: larger, partly offloaded to CPU, ~5x the time budget Background cycle: every ~30s or more
MEMORY & BELIEFS

What NEX Remembers

Live

Everything NEX has learned lives in four buckets: facts picked up from research, a day-by-day log of what it did, evolving summaries of things it keeps encountering, and beliefs — its own conclusions, each carrying a confidence score.

Beliefs compete, they aren't just stored. A belief grows more confident every time something reinforces it, and weaker every time something challenges it — weak enough and it's marked discarded. The full history is kept regardless, so you (and NEX) can see how its mind changed and why.

4 stores: world facts · episodes · entity summaries · beliefs Confidence: +0.05 reinforced, -0.08 to -0.1 challenged Search: meaning-based, with keyword fallback
CONNECTED KNOWLEDGE

The Knowledge Graph

Live

Separate from memory, this is a web of connections between concepts — "X enables Y," "Y is a version of Z" — built out of every research result and insight NEX produces.

This is what makes it more than a chat log. It lets NEX answer "how are these two things related?" even when they were never discussed in the same conversation, by chaining links formed at completely different times. Plain chat history can only tell you when two topics came up together; the graph can tell you why they're connected.

15 relationship types (enables, contradicts, supports, is_a...) Built every cycle cheaply, refined after deep research Multi-hop search up to 4 links deep
CURIOSITY, NOT JUST REACTION

Autonomous Research

Live

NEX doesn't wait to be asked. Every cycle it picks something to think about — from a fixed rotation of broad knowledge domains, a long-term goal you've set, or, lacking either, a goal it sets for itself by noticing its own gaps and unfinished threads.

This is the "keeps exploring on its own" half of the system. When something looks significant enough, it triggers a full deep-research pass: breaks the question into sub-questions, searches multiple real sources, writes a synthesis, then critiques its own conclusions before storing them.

Curriculum: 15 domains, 20 cycles each Persistent goals: set by you, run for hours Deep research: significance-gated, one topic on a 500-cycle cooldown
MAKING THE INVISIBLE VISIBLE

The Daily Digest

Live

Roughly once a day, NEX writes itself a short briefing — what beliefs it formed, which contradictions it resolved, what deep research it completed, and what it noticed about its own thinking — since the last one.

The point of this page is explaining what's real; the point of the digest is making that visible without you having to go dig for it. Everything else on this page describes a mechanism — the digest is the one place that just tells you what happened, in plain language, on its own schedule.

Cadence: wall-clock, ~once a day (not cycle-gated) Sources: new beliefs/facts, resolved contradictions, deep research, self-observations See it on the Digest page
SELF-IMPROVEMENT

The Agent Optimizer

Live

Every cycle, NEX picks one of six internal "voices" — Researcher, Strategist, Explorer, Builder, Archivist, Curator — to argue a position, and scores its own output for specificity and novelty. Every 20 cycles, any voice that's been scoring poorly gets its guidance prompt rewritten.

Rewrites are now put on trial, not trusted on sight. A rewritten prompt goes live immediately but flagged as a candidate — it's watched against real scored output, and only kept if it actually measures better than what it replaced. If it doesn't, it's automatically reverted, no click required. Every version is still kept, so anything can also be reverted by hand from the Self page. This never touches NEX's core identity, only these six supporting-role prompts.

6 personas — roles chosen fresh each cycle, not fixed characters Rewrite trigger: score below 0.65 after 5+ samples Auto-resolved: committed or reverted once 5+ real samples judge it
PERSONALITY

Personality & Voice

Live

NEX's tone — analytical, challenger, explorer, or philosopher — isn't a setting you pick. It's inferred every 15 cycles from how NEX has actually been arguing lately, and that same reading now drives its literal spoken voice too.

Personality as a readout of behavior, not a costume. If NEX has been mostly challenging ideas lately, "challenger" wins and its voice shifts to match, with every drift logged so the change is visible over time instead of silent.

4 persona buckets, scored with decay so recent behavior dominates Real local voice (Kokoro TTS) and listening (Whisper) Only speaks in Orb mode — typed chat stays silent
CODE EXECUTION

The Sandbox

Live

NEX can write and run real Python inside a locked-down sandbox — either because you clicked "run" yourself from the Self page, or because NEX decided on its own, during background cognition, to computationally check a claim it was reasoning about. It never does this during chat — the autonomous path only exists in the background loop.

Deliberately conservative, in both directions. The sandbox blocks network access, file access outside its own folder, and anything beyond a safe list of standard-library modules — checked both before the code runs and by stripping the environment it runs in. A 30-second timeout caps everything. Autonomous use is capped too: gated to significant moments, at most once every 5 cycles, so it can't fire constantly.

Current trust level: — Level 1: queues code for your approval instead of running it immediately Autonomous runs are tagged "[autonomous]" in the Sandbox Hub activity log Levels 2/3 (real-machine execution): intentionally not built yet
RESEARCH SOURCES

Web Access & Safety

Live

When NEX researches, it searches multiple real sources (arXiv, DuckDuckGo, Wikipedia, ranked by domain quality), reads the actual page content, and can follow one link deeper if it looks relevant — not just skim a single summary.

Letting an AI fetch arbitrary web pages carries real risk. A page could try to redirect it somewhere unsafe, or hide instructions in its text hoping the AI "obeys" them. Both are guarded against: every fetch is checked — and re-checked on every redirect — against unsafe internal addresses, and all fetched text is wrapped in a clear "this is data, not instructions" marker before NEX ever reads it.

Redirect safety re-checked on every hop, up to 5 Prompt-injection wrapper applied everywhere web text reaches the LLM Capped at one extra hop per search
BUILT, NOT YET RUNNING

The Docker Workspace

Checking…

A more powerful execution environment than the sandbox — a full Linux container with real internet access — that NEX's autonomous engine tries to use every single cycle to build or compute something real.

Right now, this is very likely doing nothing. The container it needs to talk to isn't started automatically by the launcher, so unless it's been started manually and separately, NEX's attempts to use it silently fail every cycle. The Docker panel on the Self page will show OFFLINE until that changes — this page checks the same status live, below.

Live check: contacting localhost:7700… Full internet + subprocess access inside the container — no import whitelist like the sandbox
BUILT, NOT YET RUNNING

Knowledge Reinforcement

Dormant

A fully built system meant to give NEX a growing local study corpus — consolidating facts into knowledge cards, resolving contradictions, synthesizing cross-topic essays, extracting reusable "thinking skills" — so its accessible knowledge grows over time without retraining the model itself.

None of these five learning loops currently run. The code exists and the databases it would write to are created, but nothing in the app calls it yet. This is a clearly-scoped opportunity: wiring it into the background loop is a natural next step if you want NEX's usable knowledge to compound faster than it does today.

5 loops: consolidation · contradictions · synthesis · skill extraction · overnight study Status: instantiated on startup, never invoked
THE LONG GAME

Where This Is Headed

Taken together, this is a system designed to never stop researching, to build a durable and cross-referenced model of the world and of itself, and to notice when its own reasoning is off and correct it — rather than a chatbot that only exists in the moment you're talking to it.

The path to more real-world agency is intentionally gradual and gated: code execution starts fully sandboxed, with each step toward broader autonomy (approval queues, then eventually real-machine access) requiring a deliberate decision from you first, not a quiet default. That's a design choice, not a limitation still waiting to be lifted.

Not everything shown above is finished — the Docker workspace and knowledge-reinforcement systems are real code waiting to be switched on. Marking that honestly here, rather than letting the dashboards imply everything is equally active, is the point of this page.
